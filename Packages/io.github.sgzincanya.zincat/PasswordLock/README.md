# Zincat 密码锁（MA）0.5.4 · 插件内置 Play 筛选

需要 Unity 2022.3、VRChat Avatars SDK、Modular Avatar 与 NDMF（AssetSaver API）。

## 使用

1. 打开 Zincat → 密码锁（MA），选择角色并添加配置。
2. 密码支持 1–20 位，数字 0–9。隐藏列表为空时扫描整个角色，支持范围与例外。
3. 点击“应用密码锁设置”，保存场景。工程只保存配置。菜单、HUD 网格/材质和内部 FX 仅在非 Play 的构建/上传时自动生成，由 NDMF 管理临时资源。插件不再创建自身 Generated 目录下的动画文件。
4. 密码锁一级菜单为“清空 / 密码”。密码内直接放 0–9，由 MA 自动分页：“0–6 / More → 7–9”。每次输入等待按钮复位。
5. 完整输入后统一判断：正确解锁，错误清空；进度不会逐位暴露错误位置。清空可随时重新锁定。
6. 默认保存解锁结果（VRChat Saved Bool，1 bit 同步预算），切换模型后恢复；关闭此项则每次加载重新输入。不保存逐位输入进度。

## 冲突提示与自检（0.5.2）

路径与组件类型重复现在只输出黄色警告，继续生成和上传。警告列出路径、组件类型和数量。不会自动改名、拆分或跳过对象；冲突对象的显隐及解锁后的原始状态恢复仍可能不完整。密码格式、角色配置等必要检查保持不变。

密码锁窗口点击“角色自检”即可检查当前角色；也可打开 Zincat → 角色路径冲突检查。自检包含未激活对象，可选择检查灯光，区分同一物体多个组件与不同物体路径重名，支持定位和复制报告。检查只读，不修改模型。检查整个选择范围，需对照密码锁局部隐藏范围与例外设置；不模拟其他插件在构建时生成的物体。

已单独安装同名自检工具时，只保留一份 ZincatAvatarConflictChecker.cs，避免重复类编译错误。

升级：退出 Play，点击一次“应用密码锁设置”，移除角色上的旧生成模块，再保存场景并重新上传。旧 Generated 资源不再更新或被新版引用，但不会自动删除，以保留其他对象可能使用的引用。不要删除并重建配置对象，参数标识需保持稳定。

## HUD

- `_Length`：圆点总数，自动取密码长度，1–20。
- `_Progress`：亮起数量，自动取输入进度；其余为空心。

最多两行，每行十个，无背景、无文字，可调整位置和大小。进度只用一个本地 Animator Float 和两段恒值动画混合，不再为每一位创建独立进度动画。包含 HUD 时，总功能片段固定为 6 个：原始显示、锁定显示、HUD 显示/隐藏、进度起点/终点。这些只进入临时构建结果，不由插件保存为工程动画文件。密码状态机仍负责计数和整串判断；着色器不能自行读取表情菜单输入。

0.5.1：单通道立体渲染下，HUD 改为双眼共同观察眼前 1.5 米的头部跟随平面，再分别使用每只眼的真实投影矩阵；兼容不对称视锥和倾斜双眼视图。删除原来的两眼直接写相同裁剪坐标方式。默认高度由 0.16 提高到 0.34，可调范围 0.1–0.8；数值越大越靠上，0.5 为参考视野中央。已有配置的高度保存在场景中，升级后需手动上调（本次工程内旧默认值已由一次性迁移处理）。仍无需进入触发范围。

隔离渲染验证：原着色器单眼渲染和立体变体编译；另以相同顶点逻辑、可控输入矩阵验证左右眼不对称投影、58/72mm 瞳距、0/10 度倾角，投影位置与共同平面的计算结果比较。测试不等于实际头显验证，需重新构建上传后确认融合舒适度。

进入密码锁一级菜单时显示，数字和 More 页内保持；返回上层或解锁后隐藏，隐藏保留进度。直接收起整个轮盘是否清零菜单参数仍需游戏实测。

已去掉相机距离触发球，无需进入特定范围。通过 IsLocal、菜单和解锁状态控制，着色器排除镜子/手持相机；较大网格边界避免正常转头被剔除。第一人称、第三人称、特殊世界和 VR 双眼仍需实机测试。Android / iOS 不生成自定义 HUD，密码锁保留。

## Unity 测试

0.5.3：移除独立 Play 预览的自动会话、键盘输入、每帧强制隐藏及灯光覆盖逻辑；窗口只显示测试说明。旧场景保存的 playPreview=true 不再生效，无需迁移场景。

0.5.4：NDMF 生成阶段内置筛选，Unity Play（包括即将进入 Play）只跳过本插件的菜单、参数、FX 和 HUD，并移除 Play 处理对象上的旧密码锁生成节点，防止旧模块继续被 MA 合并。其他 MA 组件和 NDMF 全局设置保持不变。

没有额外开关，不依赖识别 MMD 工具。筛选依据 Unity 是否处于或即将进入 Play，不检测网络上传。编辑状态下的 SDK 上传、Build & Test 和手动构建仍正常生成密码锁；Unity Play 的 Gesture 轮盘不生成密码锁菜单。进入/退出密码菜单不会绕过密码恢复模型。已烘焙进原始角色控制器的旧密码锁不属于临时模块，需要单独移除。

0.5.4 筛选回归通过：编辑状态构建生成密码锁；真实 Play 不生成密码锁资源、清理旧临时节点、保留模型显示和其他 MA 组件；随后 1 / 4 / 20 位密码 FX 回归通过。

## 验证与限制

工程实际 Unity / MA / SDK 程序集编译通过。隔离 Unity 运行实际生成 FX，并接入 Gesture Manager 相同 SDK 回调：1 / 4 / 20 位正确输入、整串错码、清空、恢复解锁、HUD 菜单/远端显隐通过；各长度均仅 6 个片段。应用设置不创建 AssetDatabase 资源且保留标识。0.5.3 已移除独立预览；隔离 Unity 真实 Play 回归通过：生成 FX 前后模型保持可见，运行 FX 后锁定，1 / 4 / 20 位正确密码恢复显示，清空后再次隐藏。实际渲染检查 1 / 6 / 10 / 11 / 20 个圆点、两行、填充、视野下方位置、相机排除和无距离限制；立体渲染变体编译检查通过，未做头显实测。

只隐藏 Renderer 和可选 Light，声音、碰撞、Contacts 和 PhysBones 仍运行。不保证加载首帧绝无闪现，不加密模型。每个角色仅支持一个锁，第三方构建/动画兼容性需实测。未直接操作用户场景的 Gesture 轮盘，未上传 VRChat。
