# 分组拍照测试版

入口：Zincat → 衣服菜单 → 分组拍照。拆分窗口的“分组拍照…”按钮可以直接带入当前源 Avatar。

1. 选择源 Avatar，读取它在拆分插件中的分组。
2. 选择一个分组，再勾选要出现在该张照片中的衣服。默认包含该分组全部衣服，拍照选择不会修改拆分内容。
3. 点击“拍摄当前分组”，或者“拍摄全部分组”。每套衣服对应一个临时角色，按默认 0.3 米中心间距横向排列，每组拍一张合照。
4. 在大图区域逐组检查，勾选“确认这张照片，可导出”。修改相机、尺寸、站位或衣服后需要重拍，旧确认不会继续生效。
5. 输入输出文件夹，点击“导出已确认照片”。支持 E:\Photos、E:/Photos、Assets/照片、工程内相对路径。相对路径不能越出工程；导出到其他位置请写绝对路径。

照片为 PNG，默认 1200×900；文件名按源 Avatar 名称和版本编号，已有同名文件会增加数字，不覆盖原文件。导出到 Assets 下会导入 Unity；导出到工程外只写普通图片。

拍摄设置可调中心间距、全身/上半身、水平角度、俯仰、画面留白、上下偏移、背景颜色和尺寸。0.3 米是角色中心之间的间距，宽衣服重叠时可调大。

测试版采用编辑模式的当前模型姿势，不运行角色动画、不执行完整的 MA/NDMF 上传构建。依赖构建阶段的形态处理应与最终模型自行核对。照片先保存在临时预览内存中，关闭窗口会释放未导出的照片。

拍摄使用独立预览场景；不移动原模型、不切换原衣服、不更改蓝图。此版本只拍摄和导出，不会设置 CAU 封面或启动上传。

## 紧凑构图与细描边

默认使用 1200×900 的 4:3 上半身合照，人形角色按标准身体骨骼确定构图，避免导入包围盒造成大面积留白。可在“背景与描边”中调节纯色背景、描边颜色、描边像素粗细、人物大小；设为 0 像素或取消勾选可关闭描边。默认外轮廓为浅灰蓝，宽 4 个输出像素。描边通过拍照后期生成，不修改模型材质。

“应用紧凑上半身构图（4:3）”可恢复参考图式的构图。更多拍摄设置保留全身/上半身、站位和角度调整。调整后旧照片需要重新拍摄并确认。旧版默认构图会迁移一次，随后保留自己调整的数值。

## 列表滚动与角色对齐

分组列表和衣服列表各自滚动，到边界后不会继续带动外层页面。角色排列使用共同的源角色原点，不再按各套衣服的最低点单独落地；鞋跟、裙摆和不对称配件不会改变整个角色的站位。拍摄姿势可在“拍照姿势”中指定。

## 拍照姿势

拍摄姿势选项：

- T Pose：标准展开双臂，默认使用。
- A Pose：手臂斜向下展开。
- 自选动画：拖入自己的纯人形 AnimationClip，设置取帧时间。

内置姿势由插件独立编写人形参数，在编辑器内存中构建，不依赖商品动画、不产生额外动画文件。旧内置姿势选择迁移成 T Pose；已选择的自选动画保留。姿势只应用于临时拍照分身，MA 衣服骨架同步跟随，修改后需重拍并确认。

## 骨骼固定机位

人形角色先以标准身体骨骼计算画面中心与大小，再应用拍摄姿势。手臂、衣服、裙摆和挂件不再改变相机的位置及缩放；人物大小、画面比例、间距、上下偏移及拍摄角度仍可调整。较大的头饰或展开的衣袖可能超出画面，需自行调整人物大小或间距。非人形模型仍使用网格轮廓作为回退。


## 编辑模式 PhysBone 模拟（测试）

在“拍照姿势”中勾选“拍摄前模拟 PhysBone（测试）”，默认模拟 2 秒，可调整为 0.2～5 秒，再点击正常的拍摄按钮。默认关闭。

只计算临时拍照分身，不切换运行模式。采用独立求解器，结束后冻结结果并恢复 SDK 全局状态；身体骨骼固定机位保持不变。仍需预览、确认后导出。

本版仅支持 PhysBone，不支持 DynamicBone。计算遵循衣服原有的重力、限制及碰撞参数：原重力为零或没有启用的 PhysBone 时，可能没有明显下垂变化。SDK 内部接口变化时可能无法计算，可取消勾选恢复普通拍摄。真实衣服效果需预览检查。

默认输出与构图预设已统一为 VRChat SDK 封面的 4:3（1200×900）。已有默认 1200×675 配置会迁移一次，保留人物大小、偏移和自定义输出位置；其他自定义尺寸不强制修改。更换比例后需要重新拍摄。

## 照片位置与导出规则

- 上传缓存默认：`Assets/Zincat/Zincat兼容/UploadSettings/Covers/<Avatar 配置标识>/V1.png`。每个 Avatar 分目录隔离，避免不同角色的 V1 互相覆盖。
- 额外导出默认：`Assets/Zincat/Zincat兼容/模型拆分/照片导出`。
- 两个位置分别保存在 Avatar 分组配置中，也会记住最近使用的位置，方便重复使用和新 Avatar 沿用。上传缓存支持 Assets 相对路径及当前工程内的 Windows 路径；额外导出可选任意 Windows 文件夹。已有自定义导出位置会保留。
- 照片确认或批量确认只表示预览通过，不会写入上传缓存。
- 点击“发送给上传”才保存对应 V 编号缓存；重复发送覆盖原文件并保留引用，不生成 `_001` 等副本，也不会开始实际上传。
- 点击“额外导出”保存独立 PNG；同名时自动添加 `_001`、`_002`，不覆盖已有导出，也不自动绑定为上传封面。
- 自动生成的上传缓存有纹理导入标记和目录说明，不能覆盖同名未标记的个人文件。缓存与额外导出都保留图片原始比例。
- 原 `UploadCovers` 缓存在 Unity 空闲、加载源 Avatar 配置后迁移到新目录，保留 GUID 和封面引用。迁移完成后仅清除空的旧缓存目录。

## CAU 独立扩展：封面与名称

1. 拍照并逐张确认或“批量确认”。
2. 点击“发送给上传”，为每组保存或覆盖 V 编号封面。
3. 在“模型拆分”的“封面与名称”中填写 VRC 模型名称；留空沿用自动名称。
4. 点击“打开 CAU 上传队列…”，检查后自行决定是否开始上传。交接本身不会上传。
5. CAU 完成模型上传后，独立扩展给确认成功的同一蓝图同步封面和名称。附加同步失败可在模型拆分窗口单独重试。

- 不修改 CAU 源码或拦截它的上传方法。
- 原版 CAU 新建模型会先拍默认封面，再由扩展换成你发送的图片；请关闭 CAU 的“默认在运行模式拍摄封面”。
- 新模型必须发送封面。已有蓝图未绑定封面时保留线上原图。
- 发送给上传的照片可在重开窗口后恢复预览，其他预览关闭后释放。
- 进行中上传使用的不可变快照和状态仍在 `Library/ZincatCauExtras`，用于防止重发照片影响已经交接的任务；清理 Library 或更换工程后重新交接队列即可。

CAU 联动代码已统一放到 `Assets/Zincat/Zincat兼容/CAU/Editor`。导出或复制插件时，请同时带上模型拆分插件及此兼容目录。

## 选择上传版本

“模型拆分”左侧每个分组都有上传勾选，旧分组和新分组默认全选。取消某组后，下次交接的 CAU 队列、封面验证及附加同步配置只包含仍勾选的版本。
勾选状态随配置保存，可点“全选上传”恢复；取消勾选不影响该组的拆分结果、衣服选择或拍照设置，也无需重新生成。全部取消时不能交接上传。修改勾选后请重新交接 CAU 队列，已经交接或已经开始的任务不会被这个勾选追溯取消。

原默认路径 `Assets/Zincat/Zincat兼容/模型拆分/照片缓存` 会在 Unity 加载配置后迁移为 `Assets/Zincat/Zincat兼容/UploadSettings/Covers`，原图片与目录 GUID 保留。此前记住的旧默认路径同步更新，其他自定义路径保持原样。

## 独立更新线上名字与封面（不上传模型）

- 在 VRChat SDK 面板登录拥有该 Avatar 的账号，分组中填写有效的已有蓝图号。新模型必须先完成首次上传；独立更新不会新建蓝图。
- 在“模型拆分 → 封面与名称”点击“仅更新名字/封面…”，可选择当前版本或左侧已勾选版本，并分别选择仅名称、仅封面、名称和封面。
- 更新封面前，先在拍照窗口确认照片并“发送给上传”；仅改名称无需照片。
- 确认清单中的名字、封面和蓝图号后开始更新。此入口直接使用 SDK 的图片与信息接口，不构建模型、不生成上传包，也不需要启动 CAU 队列或重新生成模型副本。
- 仅改封面不会改名；仅改名不会上传图片。更新时保留线上最新的其他信息，检查蓝图归属及当前登录账号。
- 模型拆分窗口显示独立更新状态；失败后可“重试同步”。账号切换、封面文件变化、重复蓝图及尚未完成首次上传的记录会阻止更新。
- 此次只进行了编译与隔离模拟测试，未实际修改线上数据。
