# 衣服分组拆分测试插件

入口：**Zincat → 衣服菜单 → 分组拆分与上传**。

## 第一次试用

1. 源角色需要已有衣服切换总菜单，占位衣服可选。
2. 打开窗口，拖入源 Avatar。自动读取或创建源 Avatar 下的“衣服拆分配置”节点，源场景按需自动保存，不再要求先手动保存。第一次默认生成“源 Avatar 名称V1”和“源 Avatar 名称V2”两个分组。
3. 选择左侧版本分组，在右侧勾选衣服。衣服名称来自对应菜单：优先使用 MA 自定义标签，否则使用菜单物体名。可搜索、全选、清空和定位菜单。窄窗口自动改为上下布局。
4. 勾选会自动记录到 Avatar 配置，并合并写入小份本地恢复记录，不会在每次勾选后保存整个场景。生成或交给 CAU 时自动保存场景，也可以按 Ctrl+S。新增分组递增版本号；调整分组顺序不会改编号，蓝图始终绑定分组固定标识。分组选项可复制、移动或移除，支持 Ctrl+Z；如需修改数字，可在“蓝图与检查”中调整版本编号。菜单改名或新增衣服后，点击刷新。
5. 点击“生成拆分模型”。结果直接放在源场景的“拆分结果 · 方案名”节点，生成完成后保存当前场景。再次生成只替换本方案上次记录的副本，不增加场景或持续堆叠模型。手动放入节点的其他对象保留。副本默认关闭，点击“预览此模型”才启用，并关闭其他生成副本。
6. 检查副本的身体、换衣菜单、分件、占位衣服、动画和 Console。生成不再全量扫描组件与动画，可按需点击“详细检查”。提示仅供参考，不直接阻止交给 CAU，最终是否可上传由 SDK/NDMF 构建验证。
7. 点击“打开 CAU 上传队列…”，确认列表后打开 CAU。**此时还不会上传**，最后由你在 CAU 点击“开始上传”，以及完成其版权确认等必要交互。

## 蓝图保存与手动分配

- 新分组首次生成时使用空蓝图，避免覆盖源模型。
- 在分组右侧展开“蓝图与检查”，填写完整 avtr_ 蓝图号后点击“应用蓝图号”。会立即保存，并同步已有副本的 Pipeline Manager；不会执行上传。点击“清空并新建”可清空蓝图。格式错误或与其他分组重复的编号会被拒绝。
- 填写已有蓝图意味着后续更新该 Avatar，需要登录拥有它的账号；本地应用编号不会验证线上所有权。
- CAU 上传结束回调会把蓝图写回方案，并保存拆分场景。上传失败但已经分配了 ID 时也保留该 ID，供重试；不会标记为上传成功。
- 后续生成沿用分组 ID，不按名称匹配。修改分组名字不会换蓝图。
- 分组与蓝图号随“衣服拆分配置”节点保存在场景或 Prefab 中。删除此节点或移除分组会失去相应本地记录，线上 Avatar 不受影响。

## 测试版边界

- 针对当前 Clothing2.0 的“直接切换 + MA 安装目标（占位衣服可选）”结构；一个源角色需只有一个已保存总菜单。
- 第一版交接只选择 Windows；会替换 CAU 窗口当前队列和清空临时拖入列表，不会启动上传。
- 配置了占位衣服时自动保留；没有配置或引用已丢失时按普通衣服模式生成，不添加空占位物体。内部沿用原默认衣服（若属于该组），否则使用该组第一套作为参数 0，不增加默认衣服选择框。
- 只移除原插件已登记的被排除衣服及其生成菜单。未登记的其他物体当作公共内容保留。
- 自动移除 MA Shape Changer 中明确指向被删除衣服的条目，保留其他条目；不自动改写共享动画或其他第三方插件配置。普通引用提示不阻止交接，是否影响使用需结合实际构建判断。
- 菜单与对象 ID 只在读取菜单时计算；勾选和改名在停止操作约 0.8 秒后合并记录配置与本地恢复备份，不触发场景保存或资源刷新。关闭窗口或编译前也会记录；Ctrl+S、生成和交给 CAU 时保存到场景，手动应用蓝图与上传完成回调仍立即保存。
- 完整复制 Avatar 或保存为 Prefab 时，衣服引用会随内部对象重新对应。跨工程迁移应带上完整 Avatar、衣服及插件依赖；单独搬配置节点不能自动匹配另一个模型。复制后蓝图仍保留，若要新建线上 Avatar，请手动清空蓝图。
- 不再为每个 Avatar 创建独立方案文件。CAU 仍需每组一份上传配置，集中放在 UploadSettings 并复用。若源场景尚未命名，会自动保存到 Data/Scenes 一次；已有源场景继续原位保存。
- 旧版 Generated 文件夹中的场景文件不自动删除；新版本生成后，方案转而关联当前源场景中的结果，不再创建新的结果场景。以前的场景如果含有手工修改，可自行保留。

内部自检不在日常菜单中显示。




## 游戏模式

运行游戏时暂停扫描和修改衣服分组，因为 NDMF/VRChat 会处理编辑器菜单组件。进入前记录配置，退出后自动清理缓存并重新绑定编辑模式的源 Avatar。分组与蓝图不应因运行时对象变化而被重新分配；运行前未选择源 Avatar 时，退出后需手动选择一次。

## 自动命名

选好衣服后，分组名为“源 Avatar 名称V编号｜衣服菜单名·衣服菜单名”，例如“纸柠V1｜兔女郎·旗袍”。名称按菜单列表顺序排列，忽略多余空白；没有勾选衣服时只显示基础名称。修改选择立即更新窗口标题和分组列表，重新生成后用于对应模型及 CAU 上传名称。仅名称变化且现有生成模型内容未过期时，可直接同步名称，保留原蓝图号；已经改动衣服的旧结果仍需重新生成。
