# 上传清单与核验

本功能属于 Zincat 独立扩展，不修改 CAU 原插件。扩展不调用开始上传；请在 CAU 中亲自确认。

## 多个角色一起上传

1. 打开“Zincat → 衣服菜单 → 模型拆分”，选择 A，生成并检查 A1、A2、A3，点击“加入上传清单”。
2. 切换到 B，生成并检查 B1、B2、B3，再次加入清单。
3. 打开“上传清单”，取消不上传的版本。清单保留加入顺序，重复加入会更新条目并保留其勾选状态。
4. 点击“打开批量上传”。扩展检查本地模型和蓝图配置，再显示交接确认。CAU 在开始上传时检查线上模型归属。
5. 在 CAU 核对六个版本后，亲自点击开始上传。拆分窗口“加入上传清单”只加入版本并打开清单，不打开 CAU。只有清单底部的交接按钮才替换 CAU 队列；CAU 已打开时可以直接替换，无需先关闭。

名称、衣服选择、蓝图或生成结果发生变化后，请点击“更新条目”或重新加入。修改衣服后还需重新生成。跨角色蓝图重复会阻止交接。关闭了源场景时，请在清单打开源场景；不会静默切换或关闭当前场景。

## 成功检测的依据

- CAU 单项完成回调必须无对应错误，返回的描述器与蓝图必须匹配，且上传前后分组快照一致。
- 完成后以当前 SDK 账号强制回读服务器，确认蓝图、所属账号、首次上传状态和 Windows 模型包。
- 上传状态依据 CAU 的结果。已有模型打开队列时不读取线上基线，上传后的查询可确认当前线上模型包；只有旧任务有交接前基线时，才比较模型包是否变化。
- 首次上传时，CAU 必须返回新的模型蓝图且服务器提供已完成的 Windows 包。
- 名称与封面独立显示结果。同步后再次回读名称和图片 URL；封面使用 SDK 返回的图片地址核对，不比较经过服务器处理的图片文件哈希。
- 核验遇到旧数据时最多读取三次，间隔两秒；单次任务超时 45 秒。网络异常、账号切换、缺少基线或包版本未变化显示“待核验”，不会冒充成功。

“重新核验（不上传）”和“重新核验全部”只读取服务器，不构建模型、不重传、不更新名称封面。模型未成功时需要重新通过 CAU 上传；核验按钮不会绕过失败结果。

当前只核验 Windows 模型包。核验通过表示服务器收到了新的模型包；不检查包内衣服的实际外观或游戏内运行效果，也不提供对服务器模型包的逐字节验证。

## 保存位置

- 清单待办在本次 Unity 会话内保留。重开窗口会读取最新拆分结果并保留勾选。同分组已经重新生成且目标蓝图一致时，自动替换清单中的模型引用。目标蓝图变化时需手动确认。可用“清空清单”一次移除所有待办。线上查询缓存保存在 `ProjectSettings/ZincatUploadQueue.json`。
- 上传事件、服务器基线与核验结果：`Library/ZincatCauExtras/queue.json`，沿用扩展原有日志。删除 Library 会丢失这些结果；不会因此自动重传。
- 不移动照片缓存，不修改原有封面与名称绑定规则。扩展会复用原 CAU 配置资产。

本次验证使用隔离 Unity 工程及本地假 CAU/假服务器；未进行真实上传或线上信息更新。首次实测请先用一个可替换的测试版本。


## HY 工程更新：服务器时间与封面

- 模型交接默认保留已有封面，不再自动附带拍照封面。新建 Avatar 所需的初始封面仍由 CAU 生成。
- 每项“更新封面…”只更新当前已有蓝图的封面，使用已确认并发送给上传的照片；会先显示确认，不上传模型、不修改名称。
- “查询服务器”查询单项，“查询所选服务器信息”批量查询。仅在点击时联网，不会在打开窗口时自动查询或上传。
- “模型上次更新”取当前 Windows 模型文件 URL 对应的确切文件版本 `created_at`，且只接受服务器标记为完成的版本。这是模型文件版本的创建时间，不等于下载或实际上传结束时间。
- 通用 `updated_at` 单独放在详情的“资料更新时间”中，它可能因修改名称、封面变化，不能当成模型更新时间。
- 无法取得文件时间时显示“服务器未提供”，不会拿资料更新时间替代。显示上次查询时间，点击查询可重新读取；没有查询不会凭本地上传时间推断。
- 模型核验状态和封面更新状态分开保留；改变封面不使模型上传记录失效。服务器查询缓存保存在 ProjectSettings/ZincatUploadQueue.json，不随插件分发。
